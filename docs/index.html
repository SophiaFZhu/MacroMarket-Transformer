01 — PHASE 4

The model ladder

Naive → persistence → logistic → random forest → LSTM → a small Transformer (60‑day window, d_model 64, 4 heads, 2 layers), each evaluated on the identical 5 walk‑forward folds over 2,650 rows of macro‑only features, 2016 – 2026. A 5‑day purge gap at every fold boundary keeps a label's forward‑return window from ever touching the test period.

03 — PHASE 5

What trading on it would have looked like

Logistic model's out-of-sample predictions, converted to a long/flat rule — long when P(up) > 0.5 — on 64 non-overlapping 5-day trades so consecutive positions never share a return window. No transaction costs modeled.

04 — METHOD

How look-ahead bias is actually prevented

Every macro row carries an observation_date (the period it describes) separate from a release_date (the day it became public). A trading day may only see rows released on or before it — enforced by the join itself, not a promise:

pd.merge_asof(
  trading_days, macro_series,
  left_on="date", right_on="release_date",
  direction="backward",
) # never returns a row released after "date"

05 — LIMITS

What would change this conclusion

  • Polymarket's window is short. 519 rows since Aug 2024 vs. 2,650 for the macro-only ladder — a small sample for a question this narrow.
  • Only Fed-decision markets were pulled. Inflation, recession, unemployment and GDP expectation markets from the original scope are still untouched.
  • No transaction costs in the backtest. ~64 trades over 2 years would erode the already-small strategy returns further.
  • No hyperparameter search against these folds — tuning against the same folds used for the final comparison would be its own form of look-ahead bias.
  • cpi_surprise is a proxy. A real surprise metric needs consensus-forecast data this project doesn't have; it's computed from month-over-month change instead.
